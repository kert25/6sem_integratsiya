# Тестовая стратегия для системы "Управление заказами"

## 1. Область тестирования
**Включено:**
- Интеграционное тестирование REST API всех сервисов
- Контрактное тестирование между сервисами
- Сквозные бизнес-сценарии
- Тестирование отказоустойчивости
- Тестирование консистентности данных

**Исключено:**
- Нагрузочное тестирование
- Тестирование безопасности (кроме базовой аутентификации)
- UI-тестирование (только API уровень)

## 2. Подходы к тестированию

### 2.1. Контрактное тестирование
**Цель:** Проверить совместимость API между сервисами
**Инструменты:** OpenAPI/Swagger, Pact (опционально)
**Охват:** Все публичные эндпоинты

### 2.2. Интеграционное тестирование
**Цель:** Проверить взаимодействие сервисов
**Подход:** Тестирование в изолированном окружении с реальными сервисами
**Сценарии:** Создание заказа, оплата, отмена

### 2.3. Сквозное тестирование
**Цель:** Проверить полные бизнес-сценарии
**Сценарии:** 
1. Регистрация → Поиск товара → Создание заказа → Оплата
2. Создание заказа с недостаточным остатком

## 3. Критерии
**Входные критерии:**
- Все сервисы развернуты в тестовом окружении
- Наличие OpenAPI спецификаций
- Доступны тестовые данные

**Выходные критерии:**
- Покрыто 100% критических сценариев
- Все обнаруженные блокирующие дефекты исправлены
- Успешно пройдены все автоматизированные тесты
